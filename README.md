# SubTerra

SubTerra — прототип приложения для трёхмерного исследования и картографирования пещер, тоннелей и помещений. Цель проекта — превращать данные сканирования в цифровую модель пространства: с границами комнат, измерениями и распознанными объектами.

**C# · .NET 9 · WPF · HelixToolkit.Wpf.SharpDX 3.1.2 / DirectX 11**

## Что уже есть

- 3D-просмотр, прогулка по виртуальным пещерам и симуляция LiDAR-сканирования.
- Синтетический трёхэтажный корпус: 18 аудиторий, коридоры, двери и лестница; этажи можно показывать отдельно и экспортировать в PLY.
- Импорт GLB со встроенными PNG/JPEG, UV и материалами, а также облаков и цветных сеток PLY, ASC, XYZ и TXT; свободный полёт по скану.
- Режим «Тоннель / шахта»: предложение маршрута по XYZ с ручной коррекцией, до 16 ветвей, сечения наклонных проходов и криволинейная сетка. Небольшая достройка выделяется оранжевым, отключается и экспортируется отдельно; оси, сетка и результаты сохраняются в проекте.
- Ходьба по наблюдаемой сетке тоннеля: высота глаз 1,65 м, объём камеры, проверка опоры, уклона, бортов и места над головой. Оранжевая достройка не служит опорой; пропуски и крупные перепады останавливают камеру.
- Геометрические классы нижней поверхности, бортов и свода по XYZ; предложения групп крепи/оборудования, ручная разметка групп и областей, экспорт XYZ с проверенными метками. Люди без RGB размечаются оператором: отдельные веса ещё не обучены.
- Несколько сканов в проекте, очистка, совмещение по опорным точкам с уточнением и предпросмотром, отмена действий.
- Измерения, метки, срез облака, сохранение проектов и экспорт PLY.
- Геометрический поиск пола, стен и потолка с проверкой классов оператором.
- Экспериментальная MLP-классификация найденных плоскостей, предварительные поверхности по точкам, условная отделка и прогулка на высоте глаз с проверкой пола и стен.
- Реконструкция помещения: выравнивание, заполнение пропусков с ограничением расстояния до измерений и плавным переходом цвета, RGB-точки предметов, подсветка достройки и отдельный экспорт модели.
- Построение сетки по кнопке для PLY без граней; достройка пола и потолка по замкнутым стенам, условные окна и скрытие внешних точек.
- Экспериментальный поиск людей: локальная YOLOX-Nano через ONNX Runtime, автоматическая подготовка ракурсов, крупный просмотр с выбором рамок и проверкой кандидатов. Классы COCO конкурируют; до 16 кандидатов каждого кадра повторно проверяются увеличенным фрагментом. Стул исключается только при уверенном совпадении всего объекта и отсутствии подтверждения человека; сидячая поза и тёмная одежда сами по себе не являются фильтром. RGB-ракурсы GLB используют треугольники и исходные текстуры.
- Выпуклые планы комнат: выбор поверхностей, площадь, периметр, высота, ручная коррекция вершин и проёмов, вид сверху и границы в 3D.
- Несколько комнат со стабильными идентификаторами и названиями этажей, общие границы и отметки проёмов.
- Геометрическое выделение предметов разными цветами, рамки, переход камеры, название от оператора, разделение и объединение групп.
- Гостевой просмотр, инструменты администратора и восстановление несохранённых данных.

## Что планируется

- Проверка на реальных сканах, невыпуклые планы, полноценная модель здания и уточнение связей помещений.
- Автоматический поиск соответствий между проходами и выборочный пересчёт зависимых результатов.
- Распознавание других предметов, разметка реальных сканов и проверка качества ИИ.
- Подключение реального сканера и работа с большими объёмами данных.

Сейчас проект работает с симуляцией и импортированными файлами. Прямое подключение оборудования не реализовано. Встроенная MLP предлагает классы пола, стен и потолка. YOLOX-Nano ищет людей на цветных ракурсах PLY и GLB. Рамки с пересекающимися 3D-границами из разных ракурсов получают общий номер. Движение во время сканирования может оставить две копии одного человека.

Войдите как администратор и откройте «Обучение» в верхней панели. Соберите рамки на цветном скане и проверьте их кнопками «Это человек» и «Ошибка». После трёх рамок каждого класса с известным источником можно обучить версию, посмотреть график и применить её для следующего поиска. Сравнение с YOLOX появится, если хватит разметки на отдельном скане. Локальная модель оценивает предложения YOLOX по признакам изображения и формы. Примеры и версии сохраняются в профиле Windows. Веса базовой YOLOX и MLP поверхностей фиксированы. Двери, столы и компьютеры автоматически не классифицируются.

Для пробы здания: «Вид» → «Модель корпуса · 3 этажа», затем выберите этаж в «Сканах» → «Только выбранный» → «Анализ». Для изменений нужен вход администратора. Готовый PLY с iPhone можно вручную перенести на ПК и импортировать с указанием единиц и оси высоты. Подробности и ограничения — в [руководстве](docs/user-guide.md#учебный-корпус-и-ply-с-iphone).

Для просмотра с текстурами экспортируйте статическую модель **GLB 2.0** со встроенными PNG/JPEG и выберите «Импорт». Метры и ось Y заданы форматом; SubTerra автоматически поворачивает модель в Z вверх. UV, нормали, PBR-карты и изображения сохраняются внутри `.subterra`, включая очистку и преобразования объектов. Экспорт PLY содержит геометрию и цвета вершин; изображения текстур сохраняйте через проект `.subterra`.

GLB с текстурами 8K/16K импортируются без прежнего отказа по суммарному числу пикселей. Исходные PNG/JPEG сохраняются внутри `.subterra` без изменения; для просмотра изображения декодируются сразу в уменьшенном размере, до 4096 пикселей по стороне. Общий бюджет вариантов текстур просмотра — 32 млн пикселей: при большом числе материалов разрешение распределяется между ними. Для цветов точек и CPU-проекций используется отдельная копия до 1024 пикселей по стороне. Сбой загрузки текстур видеокартой переключает импортированный скан в просмотр точек с сообщением, сохраняя открытый проект.

Остальные ограничения импорта GLB: до 5 млн вершин/треугольников, 32 МБ на сжатое изображение и 128 МБ изображений на проект; защитная граница исходного PNG/JPEG — 32768 пикселей по стороне и 268 млн пикселей. Нужен экспорт без Draco/meshopt, скелета и внешних ресурсов; поддерживается один набор UV (`TEXCOORD_0`). Карты одного материала должны иметь одинаковые UV-преобразования и режим повторения. Переменный `COLOR_0` поверх текстуры пока не поддерживается; постоянный цвет и нетекстурированные цвета вершин поддерживаются. Текстурированные сетки сохраняются без QEM-упрощения, чтобы не повреждать UV-швы.

Достройка интерполирует цвет только в предполагаемых участках и сохраняет измеренные ячейки. Ограничение размера пропусков действует и при достройке замкнутого контура; значение 0 отключает заполнение пола/потолка. Дверные проёмы остаются защищены. Новые фотографические детали по облаку точек не восстанавливаются.

Для проверки подземного режима откройте «Учебный тоннель · без RGB» на стартовом экране или в меню проекта. Это синтетический тоннель с уклоном и поворотом. В собственном проекте выберите «Анализ» → тип «Тоннель / шахта» → «Тоннель». Нажмите «Предложить маршрут по XYZ»: пустой редактор ищет основной проход, заданные точки служат ориентирами. Предложение появится розовой линией и строками `X Y Z`; проверьте его, исправьте координаты и примените ось. Точки также добавляются из камеры или середины измерения между бортами. Для ответвлений добавляйте отдельные именованные ветви. Выбор сечения подсвечивает профиль в 3D; «План 2D» и «Рядом» показывают его крупно.

«Построить сетку из точек» рассчитывает локальные профили всех ветвей, сохраняет форму свода, уклон и радиальные ниши. Концы не закрываются; внутренние грани на пересечениях ветвей отсекаются по наблюдаемым профилям. «Достроить пропуски до» ограничивает интерполяцию между наблюдениями; 0 отключает её. Поверхность по наблюдениям и оранжевая достройка включаются независимо; есть общий PLY и PLY только достройки. Это производная радиальная модель: нависающие полости и проходы, не описываемые одним радиусом, требуют отдельных осей и ручной проверки. Гарантия замкнутой сетки не заявляется.

После построения выберите сечение и нажмите «Прогулка по сетке». Старт ищется рядом с ним на наблюдаемой поверхности, с достаточным местом для камеры. WASD — ходьба, мышь — взгляд, Shift — ускорение, Tab — освободить курсор, Esc — обзор. Проверяется объём высотой 1,85 м и диаметром 0,5 м; поддерживаются уклоны до 45° и подъём ступени до 0,22 м. Это параметры виртуальной камеры. При отсутствии опоры, низком своде или большом перепаде движение останавливается с пояснением. Скрытие наблюдаемой поверхности завершает ходьбу; после изменения скана требуется актуальная сетка. В сохранённом проекте ходьба доступна и гостю. Внутренние грани соседних ветвей удаляются только при замкнутом профиле: открытый профиль не должен вырезать измеренный пол.

«Распознать 3D-геометрию» предлагает нижнюю поверхность, борта и свод; внутренние группы получают геометрические гипотезы крепи/оборудования. Проверьте группу в 3D и подтвердите класс. Пропущенные или склеенные объекты размечайте областью между двумя противоположными углами, заданными инструментом измерения. CSV хранит XYZ, исходный объект/индекс точки, экземпляр, предложенный и проверенный классы раздельно. Только `label_source=operator` является проверенной разметкой; автоматические предложения не превращаются в обучающие метки. Для людей без RGB нужны отдельная модель и реальные размеченные примеры — текущая сборка подготавливает их сбор, без заявления о наличии обученного детектора.

Сечения сохраняют разрывы и показывают площадь только замкнутого профиля; угловое покрытие не является точностью. Автомаршрут использует наблюдаемые нижнюю/верхнюю поверхности и свободные столбцы сетки 0,4 м; наложенные по высоте проходы следует разделять. Ось требует проверки, это не маршрут безопасного движения людей. Изменение исходной геометрии, маски, видимости или положения скана делает производные результаты устаревшими; отмена восстанавливает их. Проект использует схему 14 для ветвей, сетки и XYZ-разметки и читает прежние схемы. Вертикальные стволы и LiDAR–инерциальный SLAM пока не поддерживаются. Комнатное выравнивание и достройка окон в режиме тоннеля отключены.

## Среда и оборудование

| Компонент | Принято в проекте |
|---|---|
| Платформа | Windows, `net9.0-windows`, WPF |
| .NET SDK | `global.json`: 9.0.100 с `rollForward: latestFeature`; проверено локально на 9.0.320; CI устанавливает 9.0.x |
| 3D | HelixToolkit.Wpf.SharpDX 3.1.2, DirectX 11 |
| Проверки | Microsoft.NET.Test.Sdk 17.12.0, xUnit 2.9.3, адаптер Visual Studio 2.8.2 |
| Целевой сканер | 3DeVOK MQ; сейчас перенос файлов через 3DeVOK Studio |
| Версии комплекта MQ | Ревизия устройства, прошивка, Studio и SDK требуют фиксации по фактическому комплекту; прямой адаптер ещё не подключён |
| Справочный релиз производителя | [Studio 5.1.2.5 от 02.07.2026, соответствующая прошивка 1.0.3.3](https://3devok.com/download-center); версия конкретного комплекта не подтверждена |
| Нейросети | MLP 4–12–4 для плоскостей; YOLOX-Nano COCO для людей, ONNX Runtime 1.31.1 / CPU. Модель и лицензия включены в Assets/Models |

Откройте [решение](SubTerra/SubTerra.sln) в Visual Studio с поддержкой .NET 9 и нагрузкой разработки классических приложений .NET. Для запуска нужны Windows и DirectX 11. .NET 10 для текущей сборки не требуется.

Из корня репозитория:

```powershell
dotnet restore .\SubTerra\SubTerra.sln --locked-mode
dotnet build .\SubTerra\SubTerra.sln --configuration Release --no-restore
dotnet test .\SubTerra.Tests\SubTerra.Tests.csproj --configuration Release --no-build --no-restore
dotnet run --project .\SubTerra\SubTerra.csproj
```

Для воспроизводимой CPU-проверки больших сканов без файлов отчётов:

```powershell
dotnet run --project .\SubTerra.Diagnostics\SubTerra.Diagnostics.csproj --configuration Release -- --stress-points 5000000
```

Результат выводится в консоль; временные сканы удаляются. Это синтетическая проверка импорта, анализа, сохранения и повторной загрузки, без измерения GPU и точности устройства.

Для проверки реального скана в метрах с Z вверх: `dotnet run --project .\SubTerra.Diagnostics\SubTerra.Diagnostics.csproj --configuration Release -- --audit-tunnel "путь\scan.ply"`. Проверяются предложенная ось, сетка без достройки, места старта ходьбы, сохранение `.subterra`, экспорт и обратное чтение PLY, неизменность исходного файла и XYZ/RGB. Вывод — только консоль; собственные временные файлы удаляются. Независимые контрольные размеры эта проверка не заменяет.
